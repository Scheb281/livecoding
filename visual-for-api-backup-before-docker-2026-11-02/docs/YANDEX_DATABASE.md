## Подключение из корня проекта

Скопируй актуальный DNS-хост в консоли Yandex Cloud → кластер PostgreSQL →
«Подключение». Если публичного доступа нет, нужен доступ к сети кластера
через VPN/подходящую VM. Группа безопасности должна разрешать соединение
с твоего адреса на порт 6432.

```powershell
.\backend\scripts\Connect-YandexDatabase.ps1 `
    -HostName 'c-c9qak4sj1ph2dm3s83os.rw.mdb.yandexcloud.net' `
    -DatabaseName 'db1' `
    -UserName 'user1'
```

Пароль вводится скрыто в локальном терминале. Не присылай его в чат.
В Lockbox открой указанный секрет, затем раздел «Версии», версию
`e6qkmvcir7sfbgvdhluf` и значение ключа `postgresql_password`.
Это значение вводится в приглашение терминала; ID секрета вместо пароля не подходит.
Скрипт сначала проверяет DNS/порт, затем собирает небольшую проверку Npgsql,
проверяет соединение с `SSL Mode=VerifyFull` и `SELECT VERSION()`.
Пароль передаётся дочерней программе через stdin, а не аргумент командной строки.
Только после успеха строка сохраняется в user-secrets существующего API;
при неудачном соединении прежнее значение не меняется.

Остальные секреты приложения сохраняются. User-secrets — локальный файл
для разработки, не зашифрованное хранилище Production. Сертификат находится в
`root.crt` в корне проекта; в строку подключения передаётся полный путь,
системное хранилище сертификатов не изменяется. CA скачивается с официального
адреса Yandex Cloud `https://storage.yandexcloud.net/cloud-certs/CA.pem`.

Для создания/обновления таблиц добавь `-ApplyMigrations` к этой же команде.
Перед обновлением существующей БД сделай резервную копию. Пользователю БД
нужны права создавать таблицы и индексы в целевой схеме. Саму БД скрипт не создаёт.
Команда миграций добавит также четыре роли приложения, но не администратора.
Создание первого администратора описано в `backend/README.md`.

После настройки:

```powershell
dotnet run --project .\backend\Interview.Api
```

Проверка процесса: `http://localhost:5000/health/live`.
Проверка доступа к базе: `http://localhost:5000/health/ready`.
Для прежних открытых данных отдельно выполни `--encrypt-existing-data`
по основной инструкции, сохранив ключи от уже зашифрованных данных.

## Что было исправлено относительно примера

- В существующем API уже используется Npgsql/EF Core — второй основной
  `ConsoleApp` вместо API не нужен. Вспомогательная программа только проверяет подключение.
- Путь `Root Certificate` задан явно, имя сервера проверяется через VerifyFull.
- `VERSION()` возвращает строку; `GetInt32(0)` вызвал бы ошибку типа.
- Хост, база и пользователь передаются параметрами, пароль не записан в git.
