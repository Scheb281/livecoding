## Что проверено

- Фронтенд: lint, 12 тестов, production build.
- Сервер: 28 тестов пройдены без пропусков на PostgreSQL и Docker (Release).
- API: миграции на отдельной настоящей PostgreSQL; отсутствие расхождений модели.
- Интеграционные проверки: Identity/CSRF/права, одноразовые приглашения,
  квоты, конкурентные изменения, два SignalR-клиента, курсоры и управление,
  веса, TTL, воспроизведение, сырой шифротекст в PostgreSQL, обнаружение подмены,
  перенос открытых данных в зашифрованные.
- Реальный Docker: Python, JavaScript, TypeScript, C++, C#, Go, Java;
  ошибки компиляции и исполнения, зависание, память/вывод, отсутствие сети,
  read-only корень, отсутствие Docker socket и переноса файлов между тестами.
- Через браузер: вход кандидата → два настоящих Docker-теста успешно →
  отправка решения → сохранённое решение и события в записи сессии.

Тесты проводились на синтетических данных в отдельной временной базе.
Рабочая PostgreSQL пользователя не изменялась. Перед запуском обновлённого
приложения нужно применить миграции и выполнить --encrypt-existing-data.

## Практические границы

Это один экземпляр API, без распределённой аренды редактора и очереди.
Редактирование совместное с передачей управления, без CRDT/OT и одновременного
слияния независимых правок. Воспроизведение показывает последовательность
событий и сохранённые версии, а не видео/аудио звонка. Звонок в приложение
не встроен. Полный журнал появляется у новых событий после обновления;
старые версии кода остаются в прежней истории.

Не шифруется вся база целиком: защищено содержимое кода, тестов и общения;
индексы/пользователи/числовые оценки описаны в SECURITY_AND_EXECUTION.md.
Сохраняй ключи вместе с резервными копиями. Runner размещай отдельно от базы
и API; Docker разделяет ядро хоста. HTTPS сайта, сертификаты и TLS PostgreSQL
нужно настроить при размещении. Тесты не являются независимым аудитом безопасности.
NuGet сообщил NU1900 (недоступен индекс уязвимостей); повтори аудит перед публикацией.
