# Общий редактор через ASP.NET SignalR

В React уже подготовлен клиент. Самого ASP.NET Hub в этом проекте нет.
Поэтому пока работают локальная форма и редактор, а обмен между компьютерами
заработает после реализации сервера по описанному ниже контракту.

## Как открыть страницы

- `http://localhost:5173/?view=teamlead` — проверить форму и редактор локально.
- `http://localhost:5173/?view=teamlead&room=ID` — тимлид смотрит код комнаты ID.
- `http://localhost:5173/?room=ID` — интервьюируемый или зритель той же комнаты.

Вместо ID нужен идентификатор существующего интервью на сервере.
Параметр view только переключает страницу, права он не выдаёт.
Кнопка копирования ссылки тоже не создаёт интервью или приглашение на сервере.
Без сервера локальные задачи исчезают после перезагрузки.

## Что за что отвечает

- `teamleed.jsx` — форма, список задач, копирование адреса комнаты, редактор тимлида.
- `addquestion.jsx` — независимые поля условия и подсказки; отправка через onAddQuestion.
- `livecoding.jsx` — задания и редактор интервьюируемого/зрителя.
- `CodeBox.jsx` — Monaco. onDocumentChange сообщает об изменениях, sharedDocument
  задаёт общий код и язык, readOnly запрещает редактирование в интерфейсе.
- `useInterviewRoom.js` — соединение с сервером, вызовы Hub, получение событий,
  повторное подключение и повторный вход в группу.

Схема: Monaco → UpdateCode → ASP.NET → CodeUpdated → редакторы зрителей.
Это передача текста. Код при передаче не запускается. POST /api/code/execute
остаётся отдельной функцией, для которой нужен изолированный runner.

## Контракт Hub: /hubs/interviews

Установлен официальный npm-пакет @microsoft/signalr. Клиент уже вызывает
следующие методы. В C# назови методы именно так и сохрани порядок аргументов.

### JoinInterview(string roomId)

Проверь текущего пользователя, доступ к интервью и действительность приглашения.
Затем добавь Context.ConnectionId в группу `interview:{roomId}` и верни:

```json
{
  "language": "Python",
  "code": "print(\"Hello\")\n",
  "tasks": [{ "id": "task-1", "description": "Выведите приветствие" }],
  "canEditCode": true,
  "canManageTasks": false
}
```

Языки: Python, JavaScript, TypeScript, C++, C#, Go, Java — регистр важен.
Для нового интервью сервер должен вернуть начальный код, например шаблон из CodeBox.
Не возвращай null вместо code или tasks: нужны строка и массив.
Тимлиду возвращай canEditCode=false, canManageTasks=true.
Интервьюируемому — true/false. Зрителю — false/false.
Подсказки hint добавляй только в ответ для тимлида. Не отправляй скрытые подсказки
кандидату с надеждой спрятать их CSS: содержимое ответа видно в браузере.

### UpdateCode(string roomId, CodeDocument document)

```csharp
public sealed record CodeDocument(string Language, string Code);
```

1. На сервере заново проверь доступ и право писать код.
2. Разреши запись только одному активному подключению интервьюируемого.
   Тимлид и остальные подключения смотрят. Два независимых писателя в этой
   простой схеме будут перетирать код друг друга.
3. Проверь язык по разрешённому списку, размер текста и частоту сообщений.
4. Сохрани документ как актуальный код комнаты.
5. Отправь событие остальным соединениям комнаты:

```csharp
await Clients.OthersInGroup($"interview:{roomId}")
    .SendAsync("CodeUpdated", document);
```

Отправителю не нужно возвращать CodeUpdated: он уже видит введённый текст.
Обычное успешное завершение UpdateCode служит подтверждением вызова.
Сохраняй изменения по порядку: обновления одной комнаты нельзя записывать
параллельно без контроля версии. Для продакшена добавь номер версии документа,
защиту от устаревших событий при входе в комнату и журнал изменений в БД.

### AddTask(string roomId, NewTask task)

```csharp
public sealed record NewTask(string Description, string Hint);
```

Проверь, что текущий пользователь — тимлид именно этого интервью.
Проверь непустое условие, длину условия до 10000 символов и подсказки до 4000.
Сохрани задачу, выдай ей id, отправь полный публичный список задач:

```csharp
await Clients.Group($"interview:{roomId}")
    .SendAsync("TasksUpdated", publicTasks);
```

publicTasks содержит только id и description. Подсказки храни отдельно и
передавай только соединениям тимлида, например отдельным TasksUpdated с hint.
Так клиент кандидата не получит скрытые подсказки. Выдача подсказки кандидату
и запись факта её использования пока не реализованы.

## Подключение в Program.cs

После добавления своего класса InterviewHub:

```csharp
builder.Services.AddSignalR(options =>
{
    options.MaximumReceiveMessageSize = 256 * 1024;
});

// После builder.Build() и настройки аутентификации:
app.UseAuthentication();
app.UseAuthorization();
app.MapHub<InterviewHub>("/hubs/interviews").RequireAuthorization();
```

Это дополнения к приложению с уже настроенной аутентификацией, не весь Program.cs.
Настрой соответствующий лимит текста в UpdateCode: например максимум 20000
символов; лимит сообщения учитывает ещё JSON и UTF-8. Ограничь частоту вызовов
и число подключений на пользователя. Отклоняй запрещённые вызовы через HubException.
Не доверяй canEditCode из браузера — права проверяет сервер на каждом методе.

В текущем клиенте используется вход через cookie того же сайта. Для кандидата
сначала сделай HTTP-обмен приглашения на ограниченную серверную сессию,
после чего открывай комнату. Одна строка room=ID не должна давать доступ.
Не передавай роль admin/teamlead из URL как доказательство прав.

## Соединить Vite и ASP.NET при разработке

Клиент использует относительный адрес /hubs/interviews. Если React и ASP.NET
работают на разных портах, добавь server в существующий defineConfig в vite.config.js:

```js
server: {
  proxy: {
    "/hubs": { target: "http://localhost:5000", ws: true },
    "/api": { target: "http://localhost:5000" }
  }
}
```

5000 замени на реальный HTTP-порт своего ASP.NET. Перезапусти Vite.
На сервере используй HTTPS и проксирование WebSocket через тот же домен.
Ссылку localhost другой компьютер открыть не сможет: нужен доступный ему адрес сайта.

## Что проверить после реализации сервера

1. Войти тимлидом, создать интервью, открыть его страницу с room=ID.
2. В другом браузере пройти по приглашению как кандидат и печатать код.
3. Открыть ту же комнату зрителем: текст и язык должны обновляться у обоих зрителей.
4. Добавить задачу тимлидом: кандидат получает условие без скрытой подсказки.
5. Подключиться позже: JoinInterview должен вернуть уже написанный код и задачи.
6. Оборвать сеть и восстановить: клиент заново входит в комнату и получает состояние.
7. Попытаться вызвать UpdateCode зрителем или AddTask кандидатом напрямую:
   сервер должен отказать, даже если убрать readOnly/disabled в браузере.

Клиент пока передаёт весь текст после каждого изменения. Это простая основа
для одного автора и зрителей. Автосохранение при потере связи, подтверждение
каждой версии, совместное редактирование несколькими людьми и запись истории
для администратора потребуют отдельной реализации. При ошибке отправки появляется
сообщение; перед переподключением стоит скопировать несохранённый текст.
